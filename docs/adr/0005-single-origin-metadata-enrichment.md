# 5. 手动添加使用单域名临时权限补全公开元数据

Date: 2026-09-09

## Status

Accepted

## Context

手动输入 URL 时没有 `activeTab` 权限，扩展只能保存网址并尝试根目录 favicon，无法获知页面声明的标题、描述、图标和 Open Graph 封面。永久全站权限或批量申请多个域名会扩大可读取范围、增加安装警告和权限滥用风险。

## Decision

手动添加表单提供默认关闭的“补全网站信息”选项。用户开启后，Dashboard 只请求输入 URL 所属单一域名的可选 Host Permission；收藏项仍先进入本地 Repository，随后由 Service Worker 请求公开 HTML 并提取标题、描述、canonical、favicon 和 Open Graph 封面。

远程请求不携带 Cookie 或 Referer，使用 15 秒超时和 2 MB 响应上限，不保存原始 HTML，也不执行页面脚本。无论补全成功、失败或发生异常，都撤销该域名权限。拒绝授权或抓取失败不回滚已保存的收藏项。

批量链接与书签导入继续先保存。用户可显式开启批量补全，由浏览器一次确认本批次实际 URL 的去重域名集合；后台顺序提取与手动添加相同的 favicon 和 Open Graph 元数据，结束后统一撤销全部权限，不连续请求逐站权限。

## Consequences

- 用户可为单个手动 URL 获取更完整的公开元数据，而无需授予永久全站权限。
- 授权提示发生在明确的用户操作中，读取范围和用途可理解。
- 登录后内容、客户端渲染内容、反爬页面和跨域重定向仍可能无法补全。
- Service Worker 只保存清理后的纯文本和明确的元数据 URL，不保存或渲染远程原始 HTML。
- 批量导入只出现一次浏览器权限确认；拒绝后仍能完成基础导入。
